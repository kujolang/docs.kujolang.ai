# Ecosystem and integration ownership

## Scope and provenance

Review date: September 12, 2026. Inventory found 141 local Git checkouts, including worktrees and non-Kujo projects. A broad code/schema term sweep covered 116 checkouts whose configured origin contains `kujolang/`, finding 4,601 matching files. Leash was reviewed explicitly despite its non-organization remote. The public GitHub organization inventory is separately recorded; private and inaccessible remote-only code are not certified. A search hit is discovery evidence, not a full audit.

[evidence/inventory.json](evidence/inventory.json) pins each checkout HEAD, branch, origin and initial dirty status. [source-manifest.json](evidence/source-manifest.json) pins inspected source/document bytes. Kujo, Agents SDK and Workcell had pre-existing edits, which were preserved. All claims about dirty files apply to the recorded working-tree bytes. Runtime tests used the locally built binary identified in the verification manifest; it is not assumed to equal a released binary merely because version text matches.

[search-index.json](evidence/search-index.json) records the broad matches. Searches included the requested payment, approval, policy, secret, provider, retry, receipt and lifecycle terms, excluded node_modules, target, vendor, installed Kennel dependencies, generated output and test scratch, and then used focused source/schema/test reads. The entire ecosystem is inventoried; only relevant execution boundaries are deeply traced. There is no claim that every line or every repository test suite was audited.

## Traced contracts and rejected duplication

**Ability trace:** validate invocation → resolve definition/binding → preflight audit → host policy → input validation → approval validation → idempotency begin → approval consume → handler → output validation → completion audit → idempotency completion. `runtime.kujo:95` can replace status after audit failure; `:137` reports completion-store failure with execution evidence; `:278` onward handles handler and timeout/output status. Payments must return an accepted asynchronous operation promptly and store its outcome independently. It must not append `reconciliation_required` to Ability's existing receipt enum.

**Dispatch trace:** persist step start → inspect cached key → execute tool → validate output/check elapsed timeout → cache output → persist paused/completed state. This is workflow recovery, not a transaction spanning an external processor. Payments' own execution ID must survive new Dispatch run IDs, resumed steps and transport retries. A domain `pending` response can be a successful request result while the workflow remains paused.

**Commerce trace:** trusted catalog selection and provider configuration → checkout attempt → provider checkout/complete → normalized merchant result/webhook. Hosted `link` accepts one item/quantity one and simply returns its URL. Preserve this meaning. `commerce/src/money.mjs:6` defaults unknown currency exponent to two and `:14` parses a display-price fallback using floating arithmetic. These seller compatibility behaviors must **not** become payment authorization semantics. Share example exact-money vectors, not this implementation or a new money package without a second strict consumer.

**No new general policy layer:** application supplies authenticated principal, tenant, policy decision and approved payment profile. Payments only validates domain invariants and enforces the returned authorization. Standing budgets, delegated enterprise policy languages and aggregate spend reservations remain outside V1. If added later, their authority store must atomically reserve aggregate funds; per-payment caps alone cannot enforce a daily budget.

**Application hooks are not authorization evidence by themselves.** Ability's `validate_ability_approval` checks shape, binding and time; `consume_approval` must authenticate the issuer against stored authority. Agents SDK serializes gateway exception detail, and its general tool sanitizer can fall back to original output. The Payments transport callback must therefore return only fixed, already-sanitized errors and validated summaries. No credential can ever enter that callback's address space. This resolves the integration risk without requiring an SDK-wide behavior change.

**Policy ownership:** Fence handles static imports; Workcell handles workload constraints; Leash transports human decisions; Dispatch controls workflow/tool policy; Ability delegates consequential authorization to an application-supplied policy callback. None should be stretched into a payment-budget engine. Payments enforces immutable financial invariants and supplies typed facts to that one host callback. Daily budgets would require a separately owned atomic reservation ledger and remain excluded.
